# 问题反馈与创作者群

遇到程序异常或可复现的缺陷，建议优先在 GitHub Issues 提交反馈以追踪修复进展

![通过 GitHub Issue 记录反馈](/docs/doc-feedback-issue.webp)

## GitHub Issues 反馈标准

为了帮助开发者快速定位并修复问题，提交时请尽量包含以下要素：

1. **设备型号与系统版本**：例如「小米平板 6 Pro，HyperOS 1.0」或「三星 Tab S9，One UI 6.0」
2. **触发步骤复现**：例如「在 4K 画布使用油漆桶填充复杂线稿时发生闪退」
3. **日志或录屏附件**：若有复现录屏或导出的工程样本，将极大加速修复节奏

- [前往 GitHub Issues 提交反馈报告](https://github.com/LanRhyme/ReveriePaint/issues)

## Native 崩溃诊断拦截器

当底层 C++ 图形引擎或驱动出现异常时，系统内置的崩溃拦截器将在专用备用栈上启动捕获：

- **深度调用栈抓取**：自动抓取最多 48 帧 Native 级符号堆栈与寄存器上下文
- **Morandi 风格诊断弹窗**：崩溃发生后弹出优雅的诊断窗口，详细显示崩溃发生位置与信号量
- **一键导出诊断日志**：点击弹窗中的「复制并导出」按钮，即可将完整诊断日志保存至本地剪贴板或下载目录，直接作为 GitHub Issue 的正文附件
